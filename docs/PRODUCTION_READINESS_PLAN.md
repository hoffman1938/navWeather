# План вывода navWeather в production — полностью бесплатно ($0)

> **Версия:** 1.0 · **Дата:** 2026-10-03 · **Статус:** утверждён к исполнению (решение владельца: «ничего не должно быть платным»)
> **Решение:** [ADR-014 — Zero cost](architecture/decisions/ADR-014-zero-cost.md) ·
> **Основа:** [MASTER_AUDIT](AUDIT/MASTER_AUDIT.md) (дефекты `B-xx`, требования) ·
> **Требования:** [PROJECT_REQUIREMENTS](PROJECT_REQUIREMENTS.md) (§0 «Binding constraints»).
> Этот документ **заменяет порядок работ** из [IMPLEMENTATION_ROADMAP](AUDIT/IMPLEMENTATION_ROADMAP.md): всё платное оттуда
> исключено, остальное перенесено сюда с точными задачами.

---

## 0. Кратко

- **Цель:** довести web-приложение (PWA на Cloudflare Workers Free) до production-ready, не потратив ни копейки
  ни сейчас, ни при эксплуатации, и без платных функций для пользователей.
- **Что значит production-ready здесь** — 12 проверяемых ворот (§2): безопасные советы водителю, $0 в месяц, ядро
  работает даже при исчерпании нашей бесплатной квоты, резервные бесплатные провайдеры, соблюдение их условий,
  известные пределы ёмкости и мягкая деградация, наблюдаемость, тесты, юридические страницы, документация.
- **Объём:** 8 обязательных этапов (0–7), 60 задач, плюс 5 необязательных после запуска. **Срок:** ≈ 57 рабочих
  дней + 2 недели закрытой беты ≈ **13–14 недель** для одного инженера (≈ 8–9 недель вдвоём).
- **Главные архитектурные изменения ради $0:** планировщик Long Trip — в браузере; данные OSM для региона — заранее
  собранные статические файлы (раздаются бесплатно и без лимита); границы стран — из общественного достояния
  (Natural Earth) на клиенте; цепочки бесплатных резервных провайдеров; запрос отчётов одним «коридором»;
  экономия вызовов погоды.
- **Первые три шага:** решения владельца (§12) → этап 1 (безопасность водителя: топливо, перепланирование, ночной
  выезд, горизонт прогноза) → этап 2 (бесплатная архитектура).

## 1. Принципы (из ADR-014)

1. **Бесплатно для пользователей:** без подписок, рекламы, платных функций. Приложение — некоммерческое. Это же
   условие делает законным использование Open-Meteo free, OSRM demo, FOSSGIS и Transitous.
2. **$0 на эксплуатацию:** только Cloudflare Workers Free, поддомен `*.workers.dev`, бесплатные публичные сервисы и
   открытые данные, GitHub Actions в бесплатных лимитах. Сервисы, требующие банковскую карту, — только как
   необязательное ускорение, никогда не в критическом пути.
3. **Ядро не зависит от квоты нашего Worker:** поиск, маршрут, погода на ETA, предупреждения, навигация, план Long
   Trip работают в браузере. Worker нужен только для общего состояния (шаринг, отчёты) и серверной идентичности
   (MET Norway, приблизительное место, отчёты об ошибках).
4. **Статические данные вместо живых запросов**, где это возможно.
5. **Цепочки бесплатных резервов** для каждого внешнего сервиса.
6. **Честные пределы:** превышение бесплатной ёмкости = понятное сообщение и деградация функции, никогда не счёт.

## 4. Целевая бесплатная архитектура

```
                    Браузер (PWA) — ВСЁ ЯДРО ЗДЕСЬ, без квоты нашего Worker
 ┌───────────────────────────────────────────────────────────────────────────────────────┐
 │ поиск ──► Photon ⇄ Nominatim (кэш на устройстве)                                      │
 │ маршрут ─► OSRM demo → FOSSGIS routed-car → [свой роутер, опц.]   (очередь ≤1 req/s)   │
 │ погода ──► Open-Meteo (≤10 переменных, IndexedDB-кэш по ячейке и прогону модели)       │
 │              └─ при отказе ─► /api/v1/weather/fallback (MET Norway) ─► устаревший кэш  │
 │ карта ───► OpenFreeMap → VersaTiles                                                    │
 │ OSM-данные региона ─► /data/osm/v1/... (static assets: бесплатно, без лимита)          │
 │              └─ вне региона ─► публичный Overpass (редко, кэш на устройстве)           │
 │ границы ─► /data/borders/v1/... (Natural Earth, point-in-polygon на клиенте)           │
 │ Long Trip ─► src/trip (Web Worker в браузере)                                          │
 │ движки: ETA, выборка, сопоставление, алерты, навигация — как сейчас                    │
 └───────────────────────────────────────────────────────────────────────────────────────┘
                    │ только функции с общим состоянием (могут деградировать)
                    ▼
 Cloudflare Worker (Free) ── LiveShare DO · Reports DO (коридор) · /whereami · /weather/fallback
                             · /client-errors · /health        rate-limit binding на всё
 GitHub Actions (бесплатно) ─ CI · еженедельная сборка OSM-данных + деплой · uptime-проверки
```

## 5. Модель ёмкости (бесплатные пределы)

Допущения как в аудите: 70 % «планировщики», 30 % «водители» (2 ч навигации), 2 % делятся местоположением 1 ч.

| Ресурс | Предел | Сейчас на 1 DAU | После плана на 1 DAU | Потолок DAU | Что происходит при превышении |
| --- | --- | --- | --- | --- | --- |
| Запросы Worker | 100,000/сутки | ≈ 105 (отчёты ≤24 запроса на обновление) | ≈ 15–25 (коридор, план на клиенте, адаптивный шаринг) | **≈ 4,000–6,500** | 429 → шаринг и отчёты «временно недоступны» до 00:00 UTC; ядро работает |
| Запросы DO | 100,000/сутки | ≈ 89 | ≈ 15–20 | ≈ 5,000–6,500 | то же |
| Строки записи DO | 100,000/сутки | мало | мало (+ кэш MET Norway ≤ несколько тыс.) | > 10,000 | запись отчётов отклоняется |
| CPU Worker | 10 мс/запрос | планировщик превышает (B-23) | только лёгкие эндпоинты | — | — |
| Workers Logs | 200,000 событий/сутки | выключено | без invocation logs, сэмплирование | > 10,000 | часть логов теряется |
| Static assets | без лимита | — | приложение + данные OSM + границы | ∞ | — |
| Open-Meteo | < 10,000/сутки (на IP?) | ≈ 350 взвешенных на устройство | ≈ 100–200 на устройство | на устройство — без проблем; **если лимит на приложение — ≈ 50–100 DAU** (главный внешний риск, PR-0.5) | 429 → устаревший кэш с меткой → MET Norway |
| OSRM demo / FOSSGIS | ≤1 req/s на пользователя, fair use | ≈ 14 | ≈ 8–10 (via-пробы 4 → 2) | неизвестен (fair use) | переключение на резерв; затем «роутинг временно недоступен» |
| Photon | fair use | ≈ 30 | ≈ 15–20 (кэш, мин. 3 символа) | неизвестен | Nominatim (только по Enter) |
| Overpass | лёгкое использование | ≈ 3.5 + Worker | ≈ 0 в регионе | — | вне региона — «места недоступны» |
| GitHub Actions | приватный: 2,000 мин/мес | — | CI ≈ 6 мин/пуш, данные ≈ 15 мин/нед, uptime | публичный — без лимита | для приватного: uptime раз в 60 мин |

**Вывод:** бесплатного стека хватает на **≈ 4–6 тысяч активных пользователей в день** для функций Worker; ядро
ограничено только правилами бесплатных провайдеров. Это нужно честно указать на экране «О приложении».

## 6. Лестница деградации

| Уровень | Условие | Поведение | Где |
| --- | --- | --- | --- |
| L0 | норма | всё включено | — |
| L1 | 429 от Worker или приближение к бюджету | шаринг: обновление раз в 15 с вместо 5; отчёты: раз в 10 мин вместо 5; резерв погоды — только по запросу | `src/share/liveShare.ts`, `ReportsIncidentProvider.ts` |
| L2 | квота Worker исчерпана | шаринг и отчёты: «Бесплатная ёмкость на сегодня исчерпана, вернётся в 04:00 (00:00 UTC)»; ядро не затронуто | те же + i18n |
| L3 | Open-Meteo отвечает 429 / недоступен | устаревший прогноз с меткой; MET Norway через Worker (если L0–L1); погодный слой и уточнение точек выключены | `WeatherService.ts` |
| L4 | отказ роутинга | переход по цепочке; если все недоступны — «Маршрутизация временно недоступна», загруженный маршрут продолжает работать | `FallbackRoutingProvider` |
| L5 | отказ тайлов | VersaTiles; если оба — линия маршрута и маркеры на нейтральном фоне с сообщением | `RouteMap.tsx` |
