# navWeather — план продукта

> **Требования и архитектура** теперь в [PROJECT_REQUIREMENTS.md](PROJECT_REQUIREMENTS.md)
> (единый источник истины) и [аудите 2026-10-02](AUDIT/2026-10-02-platform-audit.md).
> Этот файл — журнал итераций продукта. Устарело: упоминания грузинского
> интерфейса (убран в §7.7) и «камеры по умолчанию выключены» (в коде включены —
> открытый вопрос №4 в требованиях).

Единый рабочий документ: куда движется продукт, что уже есть, что взять у
Google Maps, Apple Maps, Waze и Яндекс Навигатора, что должно быть на карте,
результаты UX/UI-аудита и дорожная карта. Статусы обновляются по мере работы.

**Идея продукта:** навигатор, который знает погоду там, где вы будете, и тогда,
когда вы там будете. «Знай, что впереди, до того как доедешь».

**Правила, от которых не отступаем**
1. Только реальные данные. Нет источника — функция честно помечена «недоступно»,
   симуляция всегда подписана. Сообщения водителей — всегда «сообщают», не факт.
2. Всё бесплатно для владельца: бесплатные источники (OSM, OSRM, Open-Meteo,
   Overpass, OpenFreeMap), бесплатный тариф Cloudflare, бесплатные голоса.
   Архитектура с провайдерами — платные можно подключить позже без переписывания,
   но это не требуется.
3. Приватность: никакой истории перемещений; на сервер уходит только то, что
   пользователь явно решил отправить (живая геопозиция, своё сообщение о
   происшествии, ответ «всё ещё там?»).
4. Интерфейс спокойный: сложность в движке, а не на экране. Во время езды —
   минимум информации.

Обозначения статуса: ✅ есть · 🟡 частично · 🆕 сделано в этой итерации (5) ·
⏭ следующая итерация · 🔒 заблокировано источником данных/платформой ·
✖ сознательно не делаем.

### Чего нет ни у кого (наше преимущество)
- 🟢 Погода **в момент прибытия** в каждую точку маршрута (временная шкала).
- 🟢 Сравнение маршрутов по погоде, без автоматического выбора.
- ✅ Лучшее время выезда, чтобы объехать дождь/грозу/снег.
- ✅ Предупреждение о слепящем низком солнце по направлению движения.
- ✅ Смена часового пояса на маршруте (Грузия ↔ Турция и т. п.).
- ✅ Профиль высот + температура на перевалах в момент проезда.
- ✅ Слой осадков/температуры с прокруткой времени («где будет дождь через 2 часа»).
- ✅ Погодная перестройка маршрута в пути («на перевале гроза к вашему приезду —
  объезд +8 мин»), никогда не автоматически.
- ✅ Крутой поворот + прогноз покрытия дороги в момент проезда («дорога может быть скользкой»).

## 2. Что должно быть на карте

Карта — главный экран. Слои включаются по контексту, а не все сразу.

**Всегда**
- Базовая карта день/ночь (авто по солнцу во время езды) ✅
- «Я здесь»: синяя точка, круг точности, направление ✅
- Компас (появляется при повороте карты) ✅
- Кнопка «моё местоположение» ✅

**Обзор (без маршрута)**
- Погода и качество воздуха в центре карты (чип) ✅
- Выбранное место / метка ✅, сохранённые места (значки Дом/Работа/★) ✅
- Место парковки ✅
- Слой осадков/температуры с прокруткой времени ✅
- Места рядом по категориям ✅

**Маршрут (до поездки)**
- Линия маршрута + альтернативы на карте (серые, тап — выбор) ✅
- Погодная подсветка участков ✅, маркеры погоды в моменты прибытия ✅
- Старт/финиш/остановки ✅
- Места по пути (АЗС, зарядки…) ✅
- Камеры скорости ✅ (если включено)
- Сообщения водителей на маршруте (кольцо; неподтверждённые — полые) 🆕

**Во время езды**
- Машина, пройденная часть серым ✅, камера «по ходу» с автомасштабом ✅
- Ближайшие события: погода, камеры, повороты, переезды, перерыв, сообщения водителей ✅/🆕
- Ограничение скорости и скорость ✅
- Кнопка «Сообщить» (что на дороге) и карточка «Всё ещё там?» после проезда чужого сообщения 🆕
- Никаких лишних слоёв; погода — только важные изменения

**Живая геопозиция (у получателя)**
- Движущийся маркер с именем, маршрут, пункт назначения ✅

## 4. Дорожная карта

### P0 — ядро (сделано)
Карта, поиск, маршрут по реальной геометрии, ETA по точкам, адаптивная выборка,
погода в момент прибытия, временная шкала, навигация, сход с маршрута и
перестроение, умные предупреждения, мобильная версия, PWA, живая геопозиция.

### P1 — сделано (итерации 3–4) ✅
- Боковая панель на десктопе и все пункты аудита (раздел 3).
- Лучшее время выезда по погоде; погода + AQI в центре карты; компас.
- Смена часового пояса на маршруте; слепящее солнце; камеры скорости (OSM, опционально).
- «Где я припарковался»; транслитерация грузинских названий в en/ru.
- Альтернативные маршруты на карте; значки сохранённых мест; быстрые категории.
- Профиль высот с температурой на перевалах; слой осадков/температуры с прокруткой времени.
- Крутые повороты и ж/д переезды; разъёмы и мощность зарядок; погодная перестройка в пути.
- «Продолжить путь» после случайной перезагрузки; 3D-здания при наклоне.

### P1 — сделано в итерации 5 🆕
- Сообщения водителей: клиент к готовому серверу (раздел 7).
- Самопроверка грузинского и русского текста (до вычитки носителем).
- Сквозной аудит: скриншоты 320–1920 px × светлая/тёмная × en/ka/ru, axe-core,
  клавиатура, сбои сервисов, офлайн, production-сборка через Worker.

### P1 — осталось ⏭
- Нативная вычитка грузинского и русского текста (нужны носители языка).
- Тесты на реальных iPhone/Android (нужны устройства).
- «Лежачие полицейские» (`traffic_calming`) из OSM как события.

### P2 ⏭
- Модерация сообщений водителей (жалобы, скрытие спама вручную) и юридическая проверка
  перед публичным запуском; при росте нагрузки — шардирование объекта `Reports` по регионам.
- Свой OSRM/Valhalla: объезд платных/трасс, профили пешком/велосипед (для
  велосипеда погода особенно важна: ветер, дождь).
- Офлайн-регионы (PMTiles); сохранение активного маршрута целиком (сейчас — пункт
  назначения и остановки, этого хватает для «Продолжить путь»).
- Рельеф (hillshade/terrain).

### P3 🔒 / ✖
- Пробки и ETA с пробками — нужен платный провайдер (интерфейс готов).
- Официальные ленты происшествий/перекрытий — для Грузии не найдены (интерфейс `IncidentProvider` готов).
- Цены на топливо и платные дороги — нет открытых данных.
- Навигация с заблокированным экраном, CarPlay / Android Auto — только нативное приложение.
- Street View / AR, платежи, штрафы, отметки полиции — вне идеи продукта.

## 7. Итерация 5 — сквозной аудит и доработка

Роли: продукт, UX/UI, QA, архитектура, доступность, безопасность. Внешние
сервисы в песочнице недоступны, поэтому браузерные проверки шли на dev- и
production-сборке с подменой ответов провайдеров (реальные фикстуры OSRM/Overpass)
и с **настоящим** Worker (`wrangler dev`) для `/api/*`.

### 7.1 Сообщения водителей — клиент 🆕
- `ReportsIncidentProvider` (`src/services/traffic`): маршрут покрывается
  небольшими прямоугольниками вдоль линии (≤24, каждый меньше лимита сервера
  36°²; для длинных маршрутов — крупнее, а не больше), запросы по 3 параллельно,
  поправка на разницу часов с сервером, частичный сбой не мешает (все упали —
  источник «недоступен»). `VITE_INCIDENT_PROVIDER=reports` по умолчанию.
- Сообщение → событие маршрута «ДТП · сообщают» (подтверждённые другими:
  «подтвердили 2 водителя», чуть выше уверенность); голос «ДТП впереди (по
  сообщениям)…» через обычный движок предупреждений; сообщения, которые истекут
  до нашего приезда, не показываются.
- Кнопка «Сообщить» в езде → 5 крупных вариантов (ДТП, опасность, работы,
  перекрытие, опасная погода) с подсказками; отправляется только позиция машины
  при **реальной** навигации (в симуляции варианты неактивны и это объяснено;
  без позиции, офлайн, при лимите — понятное сообщение). Голосом: «Сообщи о ДТП»,
  «Report an accident», «შეატყობინე ავარია» (вопросы вида «есть сообщения о ДТП?»
  командой не считаются).
- «Всё ещё там?» — карточка через 30–400 м после проезда чужого сообщения
  (не своего, не в симуляции), один раз на сообщение, сама исчезает через 20 с;
  «Уже нет» убирает его с карты. Обновление списка раз в 5 минут в пути.
- Карта: кольца на маршруте; «Внимание» до поездки показывает сообщения;
  панель «Данные» — «Данные сообщества / недоступно / выключено»; переключатель
  «Сообщения водителей» в настройках (выключение убирает всё сразу).
- Сервер: добавлен лимит на чтение (`REPORT_LIST_LIMITER`, 120/мин на IP) —
  все запросы списка идут в один объект. `npm run test:reports` — сквозная
  проверка сервера (валидация, CSRF, дубль = подтверждение, голоса).

### 7.5 Голос: человеческий и бесплатный 🆕
Проблема: голос звучал «как робот». Причина в коде: выбирался голос с
`localService`, а на большинстве устройств это старые синтезаторы (SAPI
«Desktop», eSpeak, «compact»), тогда как естественные голоса («Natural» в Edge,
«Google …» в Chrome, «Enhanced/Premium» у Apple) работают через сеть или
помечены в названии. Решение:
- Голоса устройства ранжируются по естественности; выбор в «Настройки → Голос»
  (с пометками «естественный», «нужен интернет») и кнопка «Прослушать»; без сети
  сетевой голос не выбирается, а если он сорвался — фраза повторяется локальным.
- **Естественный голос на устройстве** (бесплатно, открытый код, Piper): en
  `hfc_female`, ru `irina`, ka `natia` — загрузка один раз (~93 МБ), дальше речь
  создаётся на телефоне и работает без интернета. Для грузинского это часто
  единственный голос (в Chrome грузинского голоса нет).
- Надёжность: фраза получает 2,5 с на синтез, иначе её говорит голос устройства
  (поворот никогда не опаздывает); голос прогревается после загрузки и при старте
  поездки; service worker больше не стирает скачанные голоса при обновлении.
- Заодно: выключение «Голосовые подсказки» в настройках теперь сразу глушит
  речь (раньше действовала только кнопка на карте); подсказка, если на устройстве
  нет голоса для языка.
- Проверено: 413 автотестов; в браузере (production-сборка, реальная CSP) — весь
  путь с моделью-заменой (Hugging Face недоступен в песочнице): загрузка,
  фонемы en/ru/ka, синтез в worker, воспроизведение, езда без сети. Не проверено:
  звучание настоящих голосов и скорость на реальных телефонах.

### 7.6 Русский и грузинский: более человеческий голос 🆕
Что мешало звучать по-человечески (найдено прогоном всех фраз приложения через
тот же фонемизатор, что и у голоса):
- **Главная ошибка:** фонемизатор eSpeak NG теряет память на каждой фразе и
  падает примерно через 80 фраз, а после фразы с латинским названием
  («Маршрут до Batumi») — сразу. Дальше каждая фраза уходила голосу устройства,
  то есть «роботу», до конца поездки. Исправлено: свежий экземпляр из уже
  загруженных файлов (~20 мс) каждые 30 фраз, после латиницы и после любой
  ошибки. В браузере: старая сборка — 2 из 100 русских фраз, новая — 280 из 280
  (ru + ka).
- **Текст для уха:** «60 км/ч» → «60 километров в час», «-3°» → «минус 3
  градуса» (минус раньше пропадал), «ул./наб./пр.» по падежу («на улицу», «по
  набережной», «Вы на улице»), «С2» → «эс 2», скобки → паузы; по-грузински
  «12:55-ზე» → «თორმეტ საათსა და ორმოცდათხუთმეტ წუთზე», «60 კმ/სთ» (читалось
  «…наклонная черта…») → «60 კილომეტრი საათში», числа с окончаниями
  («ს 2-ზე» → «ს ორზე»), «მე-11» → «მეთერთმეტე».
- **Латинские названия** естественный голос произносит в своём алфавите:
  Khashuri → Хашури / ხაშურთან (со склонением). В русском интерфейсе названия
  населённых пунктов без русского имени теперь кириллицей (как улицы), а не
  по-английски («около Гори», а не «около Gori»).
- **Ударения:** eSpeak не понимает знаки ударения, поэтому неверно ударяемые
  слова перефразируются («с ко́льца» → «с круга»).
- **Формулировки:** «полтора / два с половиной километра» вместо «1,5
  километра», «около двух часов», «Батуми, примерно в 12:55: …», «отклонение
  примерно 5 минут»; по-грузински «ერთნახევარ კილომეტრში», исправлены
  «კილომეტრში-ზე», «გზაში … საათში» и «Batumi-მდე 16 კილომეტრში».
- **Подача:** каждое предложение синтезируется отдельно (своя интонация) и
  склеивается с паузой 0,28 с; обрезаны неровные паузы модели, мягкие края
  (без щелчков), громкость выровнена (−1 dBFS, до +12 дБ).
- **Выбор голоса:** для русского два бесплатных голоса — мужской «Руслан»
  (обучен на 31 ч профессиональной аудиокниги, первым в списке) и женский
  «Ирина»; грузинский — «Натия» (другого у Piper нет). Перед загрузкой можно
  послушать запись голоса (~80 КБ), загрузка — только по кнопке (93 МБ).
  «Автоматически» = естественный голос устройства (Edge «Natural», Siri), иначе
  загруженный естественный, иначе лучший голос устройства. Совет: в Edge на
  компьютере есть бесплатные очень естественные голоса для ru и ka.
- Заодно: меню скорости симуляции на широком экране открывалось под плашкой
  манёвра и не нажималось — теперь открывается вниз.
- Проверено: 438 автотестов; в браузере (production-сборка, реальная CSP) —
  выбор голоса, запись до загрузки, загрузка, синтез ru/ka, поездка без сети,
  axe без нарушений (ru/ka, светлая/тёмная). Не проверено на слух: звучание
  настоящих голосов (Hugging Face закрыт в песочнице, использована модель-замена)
  и ударения в грузинских названиях по-русски (eSpeak может сказать «Кобу́лети»
  вместо «Кобуле́ти»).

### 7.7 Упрощение: без грузинского, только голоса Google, «Моё местоположение» 🆕
По просьбе владельца:
- **Грузинский язык интерфейса убран** (тексты, грузинские голосовые команды,
  правила речи). Грузинские названия из OpenStreetMap по-прежнему
  показываются латиницей/кириллицей. Сохранённый грузинский язык → язык по умолчанию.
- **Только голоса Google.** Загружаемый голос Piper убран целиком (worker,
  ONNX Runtime, фонемизатор, ~30 МБ в сборке, разрешения CSP); service worker
  удаляет его кеш (~93 МБ) на устройствах, где он был. В «Настройки → Голос»
  только голоса Google для языка. Без интернета или в браузере без голосов
  Google (Safari, Firefox) говорит собственный голос браузера — подсказки не
  замолкают. Русский текст по-прежнему «расшифровывается» для голоса.
- **«Моё местоположение» при построении маршрута.** Было: если устройство не
  могло определить позицию (службы геолокации выключены, доступ запрещён, на
  компьютере нет GPS), поле «Откуда» очищалось, появлялось длинное
  предупреждение, а «Поехали» молча ничего не делал. Стало:
  - повторная попытка через GPS не только при таймауте, но и при «позиция
    недоступна» (и на карте тоже);
  - если позиции всё равно нет — старт из вашего района (уровень города) через
    собственный Worker (`/api/whereami`, данные Cloudflare о подключении,
    ничего не сохраняется, без сторонних сервисов); поле показывает
    «Примерное местоположение», уведомление называет город;
  - неудача запоминается на минуту — «Поехали» не ждёт её повторно;
  - «Поехали» с пустым полем говорит, какого места не хватает;
  - таймаут больше не называется «продолжаем попытки», когда попытки кончились.
- Проверено: 410 автотестов, сборка; в браузере — маршрут от «Моего
  местоположения», когда геолокация работает, недоступна, запрещена и когда
  недоступен и примерный район (en/ru).

## 8. Как проверять
- `npm test` — модульные и сквозные сценарии (Тбилиси → Батуми), включая сообщения водителей.
- `npm run dev` + `npm run dev:api` — локально с живой геопозицией и сообщениями.
- `npm run test:share`, `npm run test:reports` — сервер (при запущенном `npm run dev:api`).
- Панель разработчика (Ctrl/⌘+Shift+D): прыжки по времени, сход с маршрута,
  симулированный ливень/ДТП (всегда подписаны как симуляция).
- Скриншот-аудит: все состояния × 320–1920 px × светлая/тёмная × en/ka/ru; axe-core.
